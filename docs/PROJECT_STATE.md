# 电商罗盘自动化爬虫系统 - 项目状态文档

## 项目概述

**项目名称**: 电商罗盘自动化爬虫系统 (go-crawler)

**项目定位**: 多平台电商数据采集与分析管理系统

**核心价值**:
- 自动化采集抖音、快手、视频号等电商平台数据
- 提供订单分析、组织架构管理、投手管理等功能
- 支持多维度数据统计与导出

## 技术债务

### 1. 高优先级

#### 1.1 数据库连接字符串硬编码

**位置**: `config.yaml`

**问题**: 数据库连接字符串包含明文密码，存在安全风险

```yaml
database:
  default:
    link: "ly_admin:4qPbP%dd#aQs8wR@tcp(rm-2zeyw894ggx6yj3i2yo.mysql.rds.aliyuncs.com:3306)/ly_crawler?charset=utf8mb4&parseTime=True&loc=Local"
```

**建议**:
- 使用环境变量替换敏感信息
- 配置文件不提交到版本控制

#### 1.2 JWT Secret 硬编码

**位置**: `config.yaml`

**问题**: JWT Secret 使用默认值，存在安全风险

```yaml
jwt:
  secret: "go-crawler-jwt-secret-2024-change-in-production"
```

**建议**:
- 使用强随机密钥
- 通过环境变量配置

#### 1.3 飞书配置硬编码

**位置**: `config.yaml`

**问题**: 飞书 AppID 和 AppSecret 明文存储

```yaml
feishu:
  appId: "cli_a96309db59fadbef"
  appSecret: "H9UZDDSudwbXrKHko4AMVlJOBYIUTrXu"
```

**建议**:
- 使用环境变量或密钥管理服务

### 2. 中优先级

#### 2.1 缺少 DAO 层

**位置**: `internal/dao/`

**问题**: 直接在 Service 层使用 `g.DB()` 操作数据库，缺少数据访问层抽象

**影响**:
- 代码复用性差
- 单元测试困难
- 数据库操作分散

**建议**:
- 完善 DAO 层实现
- 使用 GoFrame 的 ORM 特性

#### 2.2 SQL 注入风险

**位置**: 多个 Service 文件

**问题**: 部分 SQL 使用字符串拼接，存在潜在风险

```go
query := "SELECT * FROM order_info WHERE 1=1"
if keyword != "" {
    query += " AND (sub_order_no LIKE ? OR main_order_no LIKE ?)"
}
```

**说明**: 虽然使用了参数化查询，但 SQL 拼接方式不够优雅

**建议**:
- 统一使用 GoFrame 的 Model 方式
- 避免原生 SQL 拼接

#### 2.3 缺少单元测试

**位置**: 整个项目

**问题**: 仅有少量测试文件，覆盖率不足

**现有测试**:
- `internal/logic/crawler/crawler_test.go` - 爬虫测试

**建议**:
- 补充 Service 层单元测试
- 补充 Controller 层接口测试
- 目标覆盖率 > 60%

#### 2.4 错误处理不统一

**位置**: 多个文件

**问题**: 错误处理方式不一致

```go
// 部分使用 gerror
return nil, gerror.New("查询失败")

// 部分使用 fmt.Errorf
return nil, fmt.Errorf("查询失败: %v", err)

// 部分直接返回 err
return nil, err
```

**建议**:
- 统一使用 GoFrame 的 gerror
- 定义业务错误码

### 3. 低优先级

#### 3.1 代码重复

**位置**: `kuaishou_order.go`, `shipinhao_order.go`

**问题**: 快手和视频号订单服务代码高度重复

**建议**:
- 抽取公共订单服务基类
- 使用泛型或接口抽象

#### 3.2 日志规范

**位置**: 整个项目

**问题**: 日志输出格式不统一

**建议**:
- 统一日志格式
- 添加 TraceID 支持

#### 3.3 配置管理

**位置**: `config.yaml`

**问题**: 缺少多环境配置支持

**建议**:
- 支持 dev/staging/prod 环境配置
- 使用环境变量覆盖

## 潜在风险点

### 1. 安全风险

| 风险 | 严重程度 | 说明 |
|------|---------|------|
| 敏感信息硬编码 | 🔴 高 | 数据库密码、JWT Secret、飞书密钥 |
| SQL 注入风险 | 🟡 中 | 部分 SQL 拼接方式不够安全 |
| CORS 配置 | 🟡 中 | 默认允许所有来源 |
| 文件上传 | 🟡 中 | 缺少文件类型和大小限制 |

### 2. 性能风险

| 风险 | 严重程度 | 说明 |
|------|---------|------|
| 大数据量导出 | 🟡 中 | 可能导致内存溢出 |
| 数据库连接池 | 🟢 低 | 配置合理，风险较低 |
| 爬虫并发控制 | 🟡 中 | 缺少限流机制 |

### 3. 稳定性风险

| 风险 | 严重程度 | 说明 |
|------|---------|------|
| 浏览器实例泄漏 | 🟡 中 | 异常情况下可能未正确关闭 |
| 断点文件损坏 | 🟢 低 | 文件操作缺少校验 |
| 数据库连接超时 | 🟢 低 | 已配置 maxLifetime |

### 4. 运维风险

| 风险 | 严重程度 | 说明 |
|------|---------|------|
| 日志文件增长 | 🟡 中 | 缺少自动清理机制 |
| 导出文件堆积 | 🟢 低 | exports 目录无自动清理 |
| Cookie 过期 | 🟡 中 | 需要定期刷新 |
