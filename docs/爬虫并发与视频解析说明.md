# 爬虫并发与视频解析说明

本次实现使用 Go 标准库的 goroutine、channel、WaitGroup 和 context，分别处理有限批次采集与长期后台视频直链解析。默认商品详情并发仍为 1，视频解析并发仍为 2，视频页面采集保持串行。订单同步模块不在本次改造范围内。

## 商品详情批次

- `internal/logic/crawler/crawler_concurrency.go`：先取得并发许可，再创建任务协程，避免按全部商品数量创建等待协程。
- `internal/logic/crawler/crawler_product_detail.go`：读取商品详情并发与超时配置，绑定单商品 context，并按输入顺序整理结果。
- 每个商品有独立超时；普通单项错误不影响后续商品。取消、明确的整批错误及任务 panic 会停止派发并取消批次。panic 记录堆栈。
- 批次退出前等待已经启动的任务完成清理，再允许外层释放共享浏览器。超时并不意味着可以跳过清理直接返回。

视频页面采集仍由 `video_progress.go` 逐商品执行，保留访问额度、连续空结果、保存后更新断点等行为，避免并发改变进度含义。

## 视频解析队列和同步接口

核心实现位于 `video_download_manager.go`、`video_download_queue.go`、`video_download_store.go` 和 `video_download.go`。

后台固定 worker 从有界队列取视频 ID。同步 HTTP 接口继续等待直链解析结果，后台和同步调用都经过同一个资源限额。限额在实际派发执行前取得一次，避免嵌套取得许可造成死锁。同一视频正在执行时，调用者等待同一个结果，不重复启动解析。

每个调用者的 context 控制该调用者的等待。调用者取消后不取消已经派发的共享解析任务，因为后台队列或其他调用者可能仍需要结果。共享任务由服务 context 和单任务超时控制；等待派发时取消的调用者不再派发新任务。

单任务超时覆盖策略降级、候选地址验证、重试及退避等待。HTTP 请求携带 context，HTTP 客户端另有单次请求超时；浏览器、请求拦截器和候选采集也接收 context。取消或超时后停止降级和重试，并执行页面、浏览器和启动器清理。

### 持久化状态与补投

| 状态 | 含义 |
| --- | --- |
| `discovered` | 仅发现或保存，尚未安排解析，不由补投器自动执行 |
| `pending` | 已安排解析，等待补投到内存队列 |
| `queued` | 已进入内存队列，等待执行 |
| `resolving` | 正在解析或重试 |
| `resolved` | 直链解析完成且结果已保存 |
| `failed` | 单任务超时、解析重试耗尽或不可恢复任务错误 |

队列满时，已持久化任务保持 `pending`，返回待补投状态；不会把容量不足当作解析失败。批量接口和采集日志分别报告新排队、待补投、已完成、跳过及失败数量，`pending` 与 `queued` 分开统计。

关闭 `crawler.video.autoDownload` 或手工补录时传 `resolveNow=false`，新视频保留 `discovered`。显式安排解析时才进入待办状态。历史 `pending` 已无法判断是否曾选择不解析，不自动重写旧状态；遗留数据仍按可恢复待办处理。手工补录接口继续返回 `download_status`，另提供本次待补投数量 `pending`；仅保存的 `discovered` 不计为待补投。

补投器在启动时及运行过程中扫描数据库待办，并使用稳定键的游标分页逐步填充空闲队列。每次队列容量只是本轮容量，不是恢复任务总量上限；积压超过 1000 条也会在后续轮次继续恢复。它跳过本进程已排队或正在执行的视频。失败任务使用显式重试接口重新安排，不进行无限失败重试。

服务关闭中断的任务恢复到可补投状态；数据库结果保存失败也保留待办，避免标记为成功或丢失。关闭时的状态清理使用短时独立 context，避免服务 context 已取消导致无法写入。若数据库此时不可用，会记录状态写入错误；下次启动仍扫描遗留的 `queued` / `resolving` 等状态。

## 服务启动与关闭

构造管理器或导入 controller 包不启动后台协程。`internal/cmd/cmd.go` 在数据表初始化完成后读取配置并显式 `Start(serviceCtx, options)`；配置不合法或启动失败直接返回错误。随后才启动 cron 和采集调度器。

关闭过程停止接收新任务及补投，取消执行中的解析，并通过 WaitGroup 等待清理。队列不直接关闭，避免并发入队触发 send-on-closed-channel。服务入口同时使用 GoFrame 的 `gproc.AddSigHandlerShutdown` 处理终止信号，并用 defer 覆盖入口正常返回；清理有独立的关闭超时。不可捕获的强制结束不能保证运行退出清理，持久化待办由下次启动恢复。

## 配置

默认配置在 `manifest/config/config.yaml`。以下配置变更需重启服务；并发数是资源限制，访问频率和平台额度仍由业务逻辑控制。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `crawler.productDetail.enabled` | `false` | 是否执行商品详情阶段 |
| `crawler.productDetail.concurrency` | `1` | 商品详情同时执行数量 |
| `crawler.productDetail.timeoutSeconds` | `60` | 单商品详情超时 |
| `crawler.productDetail.maxViews` | `9` | 每批商品详情访问数 |
| `crawler.video.maxDetailViews` | `10` | 每批视频页面访问数 |
| `crawler.video.maxEmptyStreak` | `4` | 连续空结果暂停阈值 |
| `crawler.video.autoDownload` | `true` | 采集后安排视频直链解析 |
| `crawler.video.resolver.workers` | `2` | 后台 worker 数，也是后台与同步解析共享执行上限 |
| `crawler.video.resolver.queueCapacity` | `1000` | 内存队列容量 |
| `crawler.video.resolver.timeoutSeconds` | `120` | 单次共享任务总超时，包含重试 |
| `crawler.video.resolver.httpTimeoutSeconds` | `15` | 单次 HTTP 请求超时 |
| `crawler.video.resolver.retryAttempts` | `3` | 包括首次在内的最大解析尝试数 |
| `crawler.video.resolver.retryDelaySeconds` | `1` | 重试退避基础间隔 |
| `crawler.video.resolver.refillIntervalSeconds` | `5` | 待办补投检查间隔 |
| `crawler.video.resolver.shutdownTimeoutSeconds` | `30` | 服务关闭等待上限 |

视频解析 worker 配置允许 1..8，队列容量 1..10000，解析尝试数 1..5；超时及间隔必须为正数并通过配置校验。并发调高前应观察浏览器内存、解析耗时及失败率。

日志及 `Stats()` 提供队列长度、执行数、成功数、失败数、重试数和累计执行耗时。累计耗时包含多个任务，与服务运行时长或单任务平均耗时不同。

## 验证与边界

回归重点包括并发峰值、取得许可前取消、单项超时、任务 panic、结果顺序、同视频合并、后台与同步共享限额、队列满补投、超过队列容量的重启恢复、取消退避等待、数据库保存失败和服务关闭。单元测试使用替身解析器及存储，不要求运行真实 Chrome、平台请求或 MySQL；race 检查覆盖并发测试。真实采集与数据库联调需单独在配置完整的环境验证。

去重及执行许可属于单个服务进程，数据库状态支持恢复，不提供跨实例租约或严格只执行一次。多实例部署需要另外设计数据库认领与租约机制。

当前 Rod v0.116.0 的启动器内部 `ResolveURL` 有未接收调用者 context 的连接探测边界。外层浏览器操作及启动器已经绑定 context 并进行清理，但不能承诺所有依赖内部阻塞都在调用者取消的瞬间退出。若此边界在部署中成为问题，需要独立评估 Rod 升级或对启动流程做更细的适配。


### 本地检查

构建检查：`go test ./... -run '^$'`。

核心回归：`go test -race ./internal/logic/crawler ./internal/service -skip '^(TestProductDetailIntercept|TestCodexExportLiCommissionCurrent)$' -count=1 -timeout=60s`。跳过的两项既有测试分别要求真实浏览器和业务 MySQL，需在合适的联调环境单独执行。模拟 HTTP 测试需要允许本机回环监听。
