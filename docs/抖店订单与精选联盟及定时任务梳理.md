## 二、抖店订单接口

### 2.1 核心文件

| 层级 | 文件 | 职责 |
|------|------|------|
| Controller | [douyin_poller.go](internal/controller/system/douyin_poller.go) | HTTP 接口：Start/Stop/Status/TriggerOrder/TriggerAlliance |
| Service | [douyin/client.go](internal/service/platform/douyin/client.go) | 封装抖店开放平台 SDK，调用订单搜索/详情 API |
| Service | [douyin/poller.go](internal/service/platform/douyin/poller.go) | 订单轮询引擎，定时拉取 + 增量保存 |
| Service | [order.go](internal/service/order.go) | 订单列表/统计/导出/导入 |
| Model | [order.go](internal/model/order.go) | `OrderInfo` 结构体（60+ 字段） |
| Model | [platform.go](internal/model/platform.go) | `PlatformOrderItem` 统一订单结构 |
| Interface | [platform/interface.go](internal/service/platform/interface.go) | `PlatformAPI` 接口定义，多平台统一抽象 |

### 2.2 订单拉取流程

#### 自动轮询（Poller）

```
Poller.Start()
  └─ gcron 注册 @every 3600s (每小时)
       └─ tick()
            ├─ 1. 查询所有已授权抖店 (store 表: platform=douyin, status=1, author=1)
            ├─ 2. 读取每个店铺的 last_poll_time 作为增量起点
            ├─ 3. 分页调用 sdk.GetOrderList (order/searchList API, 100条/页)
            ├─ 4. 响应映射: SDK类型 → PlatformOrderItem
            └─ 5. saveOrders() 按 sub_order_no 做 UPSERT
                  ├─ 补充 product_cost (从 goods 表按 seller_code 匹配)
                  └─ 计算 shop_service_fee = pay_amount × 2%
```

#### 手动触发（ManualTrigger）

```
POST /api/douyin-poller/trigger-order
  ├─ 参数: startTime, endTime, concurrency (最大45并发)
  ├─ 每个店铺独立 goroutine
  ├─ 并发分页 + 限速 45 req/sec + 3次重试
  └─ 保存逻辑同上
```

### 2.3 关键 API 对接

| 方法 | 抖店 API | 说明 |
|------|----------|------|
| `GetOrderList()` | `order/searchList` | 按时间范围搜索订单列表 |
| `GetOrderDetail()` | `order/orderDetail` | 查询单个订单详情 |
| SDK 包 | `internal/pkg/sdk-golang/` | 抖店官方 Go SDK |

### 2.4 数据存储

- **表**: `order_info`
- **唯一键**: `sub_order_no`（子订单号）
- **核心字段**: 店铺名、商品信息、支付金额、物流状态、售后状态、达人信息、来源渠道等

## 三、精选联盟接口

### 3.1 核心文件

| 层级 | 文件 | 职责 |
|------|------|------|
| Controller | [alliance.go](internal/controller/system/alliance.go) | 列表/导出/回填 buyin_id 接口 |
| Controller | [douyin_poller.go](internal/controller/system/douyin_poller.go) | `TriggerAlliance` 手动拉取 + 批量入库逻辑 |
| Service | [alliance.go](internal/service/alliance.go) | 列表/导出/达人信息回填 |
| Service | [douyin/client.go](internal/service/platform/douyin/client.go) | `GetAllianceOrderList` / `DailyPullAllianceOrders` / `QueryShopAllianceOrder` |
| Model | [platform.go](internal/model/platform.go) | `PlatformAllianceOrderItem` 结构体 |

### 3.2 两条数据流

#### 流程 A：手动全量拉取（TriggerAlliance）

```
POST /api/douyin-poller/trigger-alliance
  ├─ 参数: startTime, endTime, concurrency
  ├─ 查询所有启用店铺 (status=1)
  │
  ├─ 对每个店铺 runAlliancePull():
  │    ├─ Step 1: 查 order_info 构建 orderInfoMap (sub_order_no → 订单信息)
  │    ├─ Step 2: 加载 accountMap (short_id → uid, account_name)
  │    ├─ Step 3: 按 20 条/批拆分 sub_order_no
  │    │    └─ 并发 worker:
  │    │         ├─ 调用 GetAllianceOrderList (alliance/getOrderList API)
  │    │         ├─ batchUpsertAllianceOrders() → alliance_orders 表
  │    │         └─ batchBackfillOrderInfo() → 回填 order_info.talent_id/talent_name
  │    └─ 完成后触发 BackfillTalentInfoIncremental()
  │
  └─ 使用 order_info 中已有订单号反查联盟数据（精准匹配）
```

#### 流程 B：每日定时拉取（DailyPullAllianceOrders）

```
CronManager 定时任务 (01:30 每天)
  └─ DailyPullAllianceOrders()
       ├─ 调用 /buyin/queryShopAllianceOrder API（不同于流程A的API）
       ├─ 游标分页拉取昨日所有订单
       ├─ 解析原始 JSON（字段名与 SDK 结构不同）
       └─ 按 order_id UPSERT 到 alliance_orders 表
```

#### 两种流程对比

| 维度 | 流程A (手动) | 流程B (定时) |
|------|-------------|-------------|
| 触发方式 | 前端手动调用 | 每天 01:30 自动 |
| 使用 API | `alliance/getOrderList` | `/buyin/queryShopAllianceOrder` |
| 匹配方式 | 从 order_info 反查（精确） | 全量游标遍历 |
| 达人回填 | 即时回填 + 增量回填 | 无（需后续单独回填） |
| 适用场景 | 补数据、历史回刷 | 日常增量同步 |

### 3.3 数据存储

- **表**: `alliance_orders`
- **唯一键**: `order_id`
- **核心字段**: 商品信息、作者/佣金信息（author_account, commission_rate, estimated_comission, real_comission）、订单状态、联盟业务类型、short_id

### 3.4 达人信息回填

`BackfillTalentInfoIncremental()` 三步走（避免大表 JOIN）：

```
1. alliance_orders + account 联查 → 构建 short_id → uid 映射
2. 查询 order_info 中需要回填的订单 (talent_id 为空)
3. 按 uid 批量更新 order_info.talent_id 和 talent_name
```

## 四、定时任务系统

项目中有 **三套独立的调度系统**：

### 4.1 CronManager（主调度系统）

**文件**: [cron_manager.go](internal/service/cron_manager.go)
**入口**: [cmd.go](internal/cmd/cmd.go) 中 `RegisterBuiltin()` + `StartAll()`

#### 内置任务（5个）

| 任务名 | 显示名 | Cron 表达式 | 执行时间 | 说明 |
|--------|--------|------------|---------|------|
| `douyin_order_daily_pull` | 抖店订单每日拉取 | `0 1 * * *` | 每天 01:00 | 拉取昨日抖店订单 |
| `alliance_order_daily_pull` | 精选联盟每日拉取 | `30 1 * * *` | 每天 01:30 | 拉取联盟订单（buyin API） |
| `finance_daily_aggregate` | 达人佣金日聚合 | `0 2 * * *` | 每天 02:00 | 聚合达人佣金统计数据 |
| `order_daily_aggregate` | 抖音订单日聚合 | `0 3 * * *` | 每天 03:00 | 聚合订单统计数据 |
| `qianchuan_daily_pull` | 千川数据每日拉取 | `37 4 * * *` | 每天 04:37 | 拉取千川广告数据 |

#### DB 驱动任务

- 存储在 `cron_task` 表
- 通过 HTTP 调用配置的 API URL（支持 GET/POST）
- 支持重试和任务链（`next_task` 字段串联多个任务）
- 通过 `TaskScheduleController` 进行 CRUD 管理

#### 执行机制

```
StartAll()
  ├─ 遍历 builtin tasks → gcron.AddSingleton(cronExpr, handler)
  └─ 遍历 DB cron_task → gcron.AddSingleton(cronExpr, runWithLock)

runWithLock() 包装每次执行：
  ├─ 防重复运行（锁机制）
  ├─ TaskLogStart() → task_execution_log 记录开始
  ├─ 执行实际任务 handler
  ├─ TaskLogSuccess() / TaskLogFailed() → 记录结果
  ├─ 创建通知记录
  └─ 触发 next_task 链式任务
```

### 4.2 Douyin Order Poller（订单轮询器）

**文件**: [douyin/poller.go](internal/service/platform/douyin/poller.go)
**Controller**: [douyin_poller.go](internal/controller/system/douyin_poller.go)

独立于 CronManager 的轮询系统，有自己的 `gcron` 注册：

| Cron 任务 | 表达式 | 说明 |
|-----------|--------|------|
| `douyin_order_poller` | `@every 3600s` | 每小时拉取增量订单 |
| `douyin_poller_reset` | `1 0 * * *` | 每天 00:01 重置 API 调用计数 |
| `task_log_cleaner` | `0 3 * * *` | 每天 03:00 清理过期日志 |

**特性**:
- 日 API 调用上限：100,000 次
- 按店铺记录 `last_poll_time` 实现增量拉取
- Controller 提供 Start/Stop/Status/TriggerOrder/TriggerAlliance 接口

### 4.3 Pipeline Scheduler（爬虫流水线调度器）

**文件**: [scheduler.go](internal/service/scheduler.go)
**Controller**: [scheduler/scheduler.go](internal/controller/scheduler/scheduler.go)

专为爬虫任务设计的流水线调度：

```
product_rank → video_pool → 等待30min → 循环
```

- 3秒 ticker 检查 `product_rank` 是否到期
- `product_rank` 完成后通过 channel 触发 `video_pool`
- `video_pool` 完成后设置下一轮 `NextRunAt`

### 4.4 任务日志与告警

**文件**: [task_log.go](internal/service/task_log.go)

| 功能 | 说明 |
|------|------|
| 日志记录 | `task_execution_log` 表，状态：0=运行中, 1=成功, 2=失败, 3=跳过 |
| 失败告警 | 连续失败 5 次 → 飞书 webhook 通知（30分钟冷却） |
| 日志清理 | 7天前的日志清除 `response_body` 字段 |
| 统计接口 | `TaskScheduleController.Stats()` 查看各任务成功率 |

### 4.5 API 管理接口

`TaskScheduleController` 提供的管理端点：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/task-schedule/list` | GET | 任务列表 |
| `/api/task-schedule/logs` | GET | 执行日志列表 |
| `/api/task-schedule/log-detail` | GET | 日志详情 |
| `/api/task-schedule/stats` | GET | 任务统计 |
| `/api/task-schedule/cron-list` | GET | Cron 任务列表 |
| `/api/task-schedule/cron-save` | POST | 创建/编辑 Cron 任务 |
| `/api/task-schedule/cron-start` | POST | 启动 Cron 任务 |
| `/api/task-schedule/cron-stop` | POST | 停止 Cron 任务 |
| `/api/task-schedule/cron-trigger` | POST | 手动触发 Cron 任务 |
| `/api/task-schedule/cron-delete` | POST | 删除 Cron 任务 |
