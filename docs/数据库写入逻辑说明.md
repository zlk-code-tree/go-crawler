# 🗄️ 数据库写入逻辑说明

## 📊 当前写入策略

**批量写入**：所有 200 条数据抓取完成后，**一次性批量保存**

### 写入流程

```
爬虫启动
   ↓
第 1 页 → 第 2 页 → ... → 第 20 页（抓取中，不保存）
   ↓
200 条数据全部抓取完成
   ↓
获取商品详情（200 条）
   ↓
获取视频分析数据
   ↓
【步骤 9】批量保存到数据库 ← 这里才写入
   ↓
导出 CSV/Excel 文件
   ↓
任务完成
```

### 数据库服务
`internal/service/tiktok_ranking_list.go`

```go
func (s *sTikTokRankingList) CreateBatch(ctx context.Context, 
    data []*model.TikTokRankingListInput) error {
    
    if len(data) == 0 {
        fmt.Printf("❌ [数据库] 没有数据需要插入\n")
        return nil
    }
    
    fmt.Printf("📊 [数据库] 开始批量插入 %d 条数据...\n", len(data))
    
    db := g.DB()
    entity := (*model.TikTokRankingListEntity)(nil)
    
    return db.Transaction(ctx, func(ctx context.Context, tx gdb.TX) error {
        fmt.Printf("📝 [数据库] 开始执行批量插入...\n")
        
        result, err := tx.Model(entity).Ctx(ctx).Insert(data)
        if err != nil {
            fmt.Printf("❌ [数据库] 批量插入失败：%v\n", err)
            return err
        }
        
        affected, _ := result.RowsAffected()
        fmt.Printf("✅ [数据库] 成功插入 %d 条记录 (affected: %d)\n", len(data), affected)
        return nil
    })
}
```

## ⚠️ 可能的问题

### 问题 1：爬虫任务未完成
如果爬虫还在抓取中（比如只抓到第 5 页），数据是不会保存的。

**检查方法**：
```bash
tail -f logs/crawler-$(date +%Y%m%d).log | grep "页抓取完成"
# 应该看到：第 20/20 页抓取完成
```

### 问题 2：数据库连接失败
**检查方法**：
```bash
docker exec mysql8 mysql -uroot -proot easyadmin8 -e "SELECT 1;"
```

### 问题 3：数据为空
如果 `products` 数组为空，不会执行插入。

**检查方法**：
```bash
tail -f logs/crawler-$(date +%Y%m%d).log | grep "共获取.*条商品数据"
# 应该看到：共获取 200 条商品数据
```

### 问题 4：任务中断
如果爬虫在保存前被中断（网络问题、程序崩溃等），数据不会保存。

**解决方案**：使用断点续爬功能，重启后会从断点处继续。

## 🛠️ 优化建议

### 方案 1：每页保存一次（推荐）
**优点**：
- 数据丢失风险小
- 内存占用低
- 可以随时查看进度

**缺点**：
- 数据库写入频繁
- 可能影响性能

**修改位置**：
```go
// 在 scrapeAllPagesWithCheckpoint 函数中

    // 抓取当前页
    products := s.scrapeCurrentPage(ctx, page, taskId)
    
    // 每页保存一次
    if len(products) > 0 {
        s.savePageData(ctx, taskId, products) // 新增函数
    }
    
    // 点击下一页
    // ...
}
```

### 方案 2：分批保存
每抓取 50 条保存一次（折中方案）。

### 方案 3：当前方案（批量保存）
**优点**：
- 数据库写入次数少
- 性能好

**缺点**：
- 内存占用大
- 中断风险高
